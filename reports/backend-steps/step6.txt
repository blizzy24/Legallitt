Step 6 — Documents (architecture v3.6, through 6d)

Implemented
- Authenticated presign, complete, download-URL and delete endpoints.
- Direct multipart S3 upload with a signed size/type/key policy. Completion
  reads S3 metadata, validates file structure and records real size/type/pages.
- PDF page counting (including ID proof); JPEG and PNG count as one page.
- Case ownership/assignment/admin access applies to every document endpoint.
  Unrelated clients/advocates receive 404 without a URL. Pending/deleted evidence
  is excluded from case responses and cannot get a download URL.
- UUID-based keys; temporary uploads are copied by exact version to immutable
  validated keys so reuse of a signed upload cannot replace accepted evidence.
- Scheduled cleanup for abandoned rows; version-aware storage deletion and
  retries for failed deletions, preserving document metadata/history relations.
- ID proof remains evidence, not KYC. API supplies the v3.6 alternatives and
  masked-Aadhaar-only guidance. No OCR/text/identity-field extraction. Identity
  files get the same structural page counting as other files.
- Compute IAM source now permits version reads, listing and version deletion.
  Synthesized only; no AWS infrastructure deployment.

Implementation decisions beyond the document's exact details
- Five-minute upload/download expiry; cleanup every five minutes while an API
  process is running. Row locks coordinate concurrent requests and cleanup.
- 25 MB interpreted as 25,000,000 bytes. Signed multipart POST rather than PUT
  enforces that limit at S3. File field must be appended last.
- Internal staging filename is prefixed .pending-; final keys follow the exact
  cases/<caseId>/<documentId>/<filename> pattern. Clients cannot write final keys.
- Completion internally reads the S3 object to validate/count its structure.
  Client upload/download bytes are never proxied through API endpoints.
- Delete is allowed for uploader/admin only, with current case access required.
  Metadata is tombstoned, while every S3 version/delete marker is purged. Failed
  physical deletions retry on the scheduled sweep.
- PDF inspection: ten-second worker timeout and 128 MB V8 old-generation limit;
  encrypted/malformed PDFs that cannot be counted are rejected. Parser output
  is discarded. Format validation is not a malware scanner.
- Metadata rejects path/template expressions, control characters and full
  twelve-digit identity-number patterns. It does not inspect image identity
  content or establish that an uploaded ID has been masked.
- Existing Legal Notice case scope is retained; other service flows are not
  implemented here. Non-ID document kinds remain caller-supplied validated
  identifiers; no unsupported product taxonomy invented.
