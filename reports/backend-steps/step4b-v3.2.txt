Step 4b update — architecture v3.2

Changed:
- OTP request accepts but ignores the displayed phone number; it does no lookup.
- OTP verify requires code 123456 and a client/advocate role selected by the
  existing onboarding picker. It authenticates only the specified seeded account
  with USER_PASSWORD_AUTH. The normal JWT verification, /me, refresh and role
  guards apply. No second session type or request-time provisioning was added.
- Demo OTP requires ENVIRONMENT=dev, PHONE_AUTH_MODE=demo, and NODE_ENV other than
  production. Missing/unknown mode and live mode fail closed. No SMS is sent.
- Login without a role selection goes through the existing picker and returns to
  login. Normal signup still uses that picker for the registration role.
- Kept OTP visuals; carried the selected role in in-memory pending login state.
- Updated the operator README and automated browser authentication check.

Implementation details not specified by the document:
- /auth/otp/verify adds a required role field restricted to client or advocate.
  Missing role is rejected rather than silently defaulting. The verified token's
  role must match the requested demo role. Phone input is never an identity.
- Demo credentials are read server-side from Secrets Manager, never mobile.
