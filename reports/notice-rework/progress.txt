Legal Notice rework — backend simulator stage (26 October 2026)

Completed:
- Applied architecture v5.1 migration locally: auth_events, case_events.source,
  payments.payer_id (existing rows backfilled from case client), simulation
  columns on payments and notifications. case_events.case_id remains NOT NULL.
- Payments, notifications and phone-auth each have a port, simulator and
  module-time selection. Defaults are simulated; phone also accepts the existing
  demo spelling. Live selection fails startup because live adapters/credentials
  are not configured. No AWS deployment.
- POST /payments/intents replaces /dev/cases/:id/pay. The shared client sends
  Idempotency-Key and retries preserve it. Payment capture, payer, event,
  notification and initial-fee lifecycle transition commit atomically. Courier
  payment is advocate-paid and leaves approved/dispatching unchanged.
- Phone attempts and email registration/login outcomes are audited.
  Auth events store only identifier, event/outcome, optional user id, simulation
  flag and database timestamp. The optional IP/user-agent columns remain empty.
  No OTP, password or token is persisted in auth_events.
- Auth diagnostic fix from 86073e3 remains: detail outside production, redacted
  logs in every environment. Simulated OTP failures also carry simulated=true.

Verification:
37 API tests passed on local PostgreSQL 16; all workspace typechecks passed.

returned real tokens and simulated=true. Invalid-password registration returned
400, 'Password must include a symbol', with redacted ZodError detail.
The temporary server was stopped; the existing port-3001 process was not replaced.
